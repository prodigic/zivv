# Weekly run-state foundation

First implementation slice of #31, stacked above the optional preflight PR #46. `src/lib/ingestion/weekly-run-state.ts` provides a pure versioned state validator, deterministic run identity, guarded transitions and stage receipt checks for the [delivery contracts](weekly-stage-contracts.md).

This module does not execute stages, write journals, lock other processes, import sources, change weekly state, deploy or send notifications. Existing manual commands remain the supported Friday path. Durable private persistence, fencing, side-effect reconciliation, candidate generation after input drift, correction releases and actual orchestration remain #31 implementation work; this PR does not close #31.

The source identity binds edition/delivery, raw hash, rules hash and original import observation time. Receipts bind prepared content and reviewed report/revision to the import, then bind frozen membership/configuration to the export and match candidate artifacts, deployment/destination and publication cutoff. The initial edition cutoff must be strictly after the import observation to include it in a half-open window. Later stages cannot bypass unfinished predecessors. A running stage stays running after deserialization: recovery must inspect actual durable side effects and provide completion/failure evidence rather than silently reset and repeat it. Serialized revisions must agree with the attempt/completion counts, preventing corrupt checkpoints from resetting the stale-input guard.

The revision guard protects pure transitions from stale inputs; it is not a cross-process compare-and-swap or distributed lock. The future writer must enforce the expected revision atomically and fence stale owners. Receipt syntax/matching does not prove a deployment occurred or that no pending batches exist; workers must obtain those facts from maintained commands/store indexes and live checks before supplying evidence. Failed or blocked attempts can restart; succeeded stages are immutable within a run. Changed inputs need a reviewed successor-run/candidate policy, not altered old receipts.

Tests cover full sequence/round-trip, skip prevention, interrupted running stages, retries, stale revisions, source/rules drift, snapshot mismatch, changed candidate/artifact/deployment, cutoff mismatch, future freeze, pending prior batches and malformed state. No live catalog is touched by these tests.
